# Refreshing the MorphHB Global Audit

The full Old Testament morphology inventory is generated by `.github/workflows/refresh-morphhb-audit.yml` using `scripts/audit-morphhb-global-morphology.mjs`.

## Branch and trigger rules

1. Start a dedicated branch named `chore/morphhb-audit-refresh-<date-or-suffix>` from the current `feat/biblical-research-sources` tip.
2. Keep the audit branch name under the `chore/morphhb-audit-refresh-*` pattern. The workflow's push filter includes the workflow file itself, the audit script, and the two morphology source/test files.
3. Push the trigger change or the relevant source/test update to that audit branch. The job checks out Open Scriptures MorphHB into the runner temporary directory, records the upstream source commit and test-file blob SHA, regenerates the Markdown/CSV inventory, uploads the results as an artifact, and commits changed report files only to the audit branch.
4. Open or update a PR targeting `feat/biblical-research-sources`. Do not push generated report changes directly to the canonical integration branch.

## Validation

The audit-generation job succeeding is not a replacement for project CI. Merge the PR only after Typecheck, Test, Lint, and Build all pass for the current PR head. If a report commit authored by `github-actions[bot]` causes a newer pull-request CI run to show `action_required`, first inspect the actual latest head SHA. A subsequent owner-authored commit on a path outside the audit workflow's trigger filter can cause CI to validate the current head without starting another audit run.

## Reading the report

The Markdown report summarizes coverage and lists high-frequency gaps; `morphhb-global-morphology-codes.csv` is the full exact-code inventory. The report records the MorphHB commit, BSMP audit commit, and exact test-file blob SHA. Test coverage is counted only when the complete source morphology code appears as a literal argument to `parseHebrewMorphology(...)`. Coverage counts are source-specific: test literals that are not morphology codes occurring in the audited OT source do not add to the distinct-code coverage numerator.
